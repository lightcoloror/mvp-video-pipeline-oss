## 2. 语义驱动画面，复用现有时钟

以既有 packaging 场景计划为时间真源，复用 audio_timeline、语义动效、对象场景、字幕和单一 FFmpeg 出口。不要建立第二套渲染、ASR 或时间轴。

在现有 scene plan 的说明/sidecar 中记录下列设计信息；未经 schema 支持不直接增加运行时字段：

| 信息 | 必填内容 |
|---|---|
| 语义事件 | 稳定事件 ID、原句/歌词或证据引用、源与成片区间、触发词/动作 |
| 时间依据 | 原音实测/人工核对/字幕投影/近似插值，区分精度与待核项 |
| 信息分工 | 声音已经说了什么；画面新增什么关系、变化或证据；本镜结束时屏幕保留什么关键信息及多久 |
| 对象状态 | 稳定对象 ID、角色、位置/尺寸及坐标系、姿态、可见性、道具、文字 |
| 镜头与颜色 | 景别、机位/缩放、材料色/语义色/品牌标注的理由 |
| 交接 | 入场状态、出场状态、接续对象、转场类型、负责绘制重叠部分的镜头 |

先选最需要画面的少数位置，保留必要的讲述者镜头。优先已有合适素材；示意素材标记为示意，不能冒充具体人、品牌或事件的真实现场。新增收费/生成服务按实际授权处理，不因附件推荐而自动调用。

让视觉对象承担叙事：例如同一笔款项由预算进入第一阶段，再显示余额与第二阶段支付；避免与语义无关的装饰运动。同一对象保持身份、材质和语义颜色；保留证据原色，编辑标注独立分层。

不同版本音频可用已核实锚点映射辅助动画草案，但近似插值不等于词级同步。校验锚点单调性、重复时间、缺口与速度变化；不得按全长比例推算剪辑后字幕。真实口播沿用样本时钟与显式剪辑映射。

SRT 可提供句级初始定位，但时间格式精细不代表识别/对齐准确，也不自动提供词级触发点。必须绑定实际音频版本和剪辑映射；在剪映等外部编辑器改序、变速或删段后，先回收映射并更新 packaging，再重投影字幕、动画与音效，不能只改字幕时间或沿用旧成片的检查结果。

关键动作沿用现有 cue ID，区分入场、接触/变化、落定等需要声音反馈的时刻，并说明采用哪个时刻。将其交给既有动作提示音流程（原链接 `脚本与动效同步提示音MVP-2026-08-31.md`：公开快照缺件、未核实，不随公开版分发），不手写第二份独立时间表；有意提前/延后需记录偏移与原因，修改动作后同步更新依赖，并试听实际混音。适配器按动画参数推导的落点仍是候选，需与实际动作和听感核对，不能称为逐动作实测卡点。

公开快照中该流程的可核实落点是 `video-stock-media`（`stock_media_cli:main`）及所给的 `stock_media.py` / `stock_media_cli.py`：时刻类型对应 `SFX_VISUAL_TRIGGERS = {onset, impact, settle}`，时间依据对应 `SFX_TIMING_AUTHORITIES` 与 `timing_authority`，`cue_id` 唯一性与 `timeline_start_s` 构成同一份 cue 计划；计划/校验接口为 `build-sfx-cues` → `build_sound_effect_cue_sheet` / `validate_sound_effect_cue_sheet`、`build-sfx-plan` → `build_sound_effect_edit_plan` / `validate_sound_effect_edit_plan`，另有 `validate` / `doctor`。三层须分清：①候选时序由 cue sheet 的 `candidate_cues_only=True`、`source_timeline_modified=False`、`spotting_status=needs_audition` 与 edit plan 的 `render_eligible`、`ffmpeg_handoff.executed=False` 表达；②外部素材依赖本地已授权素材与 license snapshot（`ingest` / `build-sfx-profile` / `build-catalog` / `list-sources`），源码明确 `automatic_download=False`、`network_execution_performed=False`、缺素材时 `missing_material_fail_closed`；③真实音效执行是 `mix-sfx` → `execute_sound_effect_mix` → `execute_ffmpeg_with_receipt`（需本机 ffmpeg），接口存在但本轮未运行，不构成实测验收。“有意提前/延后需记录偏移与原因”属上层/人工记录要求：所给 `stock_media.py` 提供绝对 `timeline_start_s`、`rationale` 与 `evidence_ids`，未见显式 offset 字段，此项未核实。

### 2.1 先看静态设计，再验证运动

- 新系列、新风格或明显改版先做代表性静帧，检查信息层级、长中文、字体、对象比例、留白、安全区和手机实际显示效果。配色服从材料、事实和表达，不因参考作者使用 IP 形象就把整片改成品牌配色。参考图分别标明借鉴画风、构图还是运动，不默认整张照搬；封面同样区分画风与构图参考。
- 再用同一组对象制作数秒动态样片，覆盖最复杂的一次状态变化及交接。检查原因与结果、受力反馈、惯性/跟随、阅读停留、镜头运动及对象连续性；弹性、挤压和拉伸按表达需要选用，不把某套动画原则变成每镜必须出现的特效。
- 静态与动态结果分别记录通过项、问题和证据，再决定是否扩展到其余镜头；稳定复用的风格检查本次变化即可，不机械重做整套测试。需要用户审美选择时呈现具体样片和取舍，已有明确选择继续沿用。
- 关系、流程、数量变化优先评估现有 SVG/MG/对象组件能否说清；纹理、人物表现或真实证据需要相应素材时沿用原素材路线。矢量源便于编辑和缩放，但字体、栅格贴图、滤镜与最终输出分辨率仍须检查，不能把“代码画图”当作质量保证。

上述说明写入现有 scene plan/sidecar，复用语义编辑与视觉节拍中的语义触发与信息推进字段（原链接 `语义编辑与视觉节拍候选SOP-2026-09-05.md`：公开快照缺件、未核实，不随公开版分发）。现有动效标签的近整句复述检查只是文本启发式；通过它不代表画面已经提供了有效的解释，普通对白字幕也不属于需要删除的冗余动效标签。

- 程序化画面应由时间、固定参数和固定种子决定；避免依赖上一帧状态、运行时随机数或墙钟。固定字体、画布、渲染依赖和资产版本，避免把单机稳定误称跨环境像素一致。

- 继续使用现有内容哈希与片段缓存。修改共享资产/接缝时检查两侧及所有依赖镜头；并行分块本身不构成增量缓存。
- 并发按实测 CPU、RAM、显存、子进程峰值和磁盘余量决定，出现资源压力先降并发，不写死单并发，也不照搬参考项目的 17 路并发。

## 4. 分层验收及交付阻断

1. 资产层：检查字体字符覆盖、姿态、朝向、道具与多对象一致性。缺字和字号是两项检查。
2. 场景层：检查语义触发前后、文字最长/最多时刻、动作极值与对象遮挡；均匀抽样仅作补充。
3. 接缝层：查看前镜末帧、约定交接状态、后镜首帧，并播放接缝前后短片；按实际帧率取帧。像素差仅用于预期连续的接缝，不能用平均差值替代感知判断。
4. 诊断层：固定或关闭颗粒等装饰噪声比较结构；最终带完整效果的版本仍需复核。重点对象局部差异与全帧差异分开看。
5. 成片层：沿用 final_layout_safety、typography_gates、字幕覆盖、音画同步、裁切、音频与完整解码检查；按实际手机显示尺寸检查字号，而非只看 1080p 原尺寸截图。复核开头完整语句、片尾完整动作/笑声和音频尾巴。
6. 交付层：未处置的渲染错误、空镜、必需字幕缺失、关键对象截断或检查失败，阻断 ready/验收通过。保留失败候选用于诊断，不把“文件生成成功”当作成功验收。技术通过与人工语义/试听通过分别记录。

接缝、语义、字幕的检查证据写入现有 review packet/报告附件，绑定候选哈希、帧率、时间区间、方法和结果。没有执行的检查明确标记未执行。本文件新增的接缝合同与检查目前是人工执行规范，未提供自动像素比较 CLI。

对计划中的每个必需语义事件建立覆盖记录，复用现有事件 ID，不另建时间真源。至少列出：事件 ID、原句/歌词或动作、成片区间、承载镜头、检查证据、结果。口播/歌词包括有意重复的句子；完整笑声等保留事件单列。多个事件由同一镜头承载时逐项关联；保留主讲人画面也算有效承载，不为填表强加补镜。合并、删除或取消必需事件必须写明原因和对应编辑决定，不能通过删掉记录掩盖缺漏。待检查、缺证据、未覆盖与通过分开记录；未处置的必需事件缺漏阻断验收通过。

覆盖记录可直接附在现有 review packet，示例格式如下（内容仅示意）：

| 事件 ID | 表达/动作 | 成片区间 | 承载镜头 | 检查证据 | 结果/处理 |
|---|---|---|---|---|---|
| cue-01 | 第一笔支付 | 以 packaging 为准 | scene-01 | 同一候选的触发前/后帧与短片 | 待检查 |
| cue-02 | 余额发生变化 | 以 packaging 为准 | scene-01 | 变化后状态与原句核对 | 待检查；与 cue-01 共用镜头 |

有覆盖记录仍不代表字幕和语义正确：需核对原声、实际画面及对应时间；检测器或抽帧脚本产出的是检查材料，不能自动代替这一步。

## 5. 持续复用与局部修改

每个项目在现有复盘/集成记录中写：问题触发条件、证据时间、根因、采取的修复、影响组件、复用范围、验证结果。高频问题转为现有组件参数或回归检查，不再创建散落的重复规则。

复用组件、片头片尾或开始相邻镜头前，先查与该组件、画幅和转场有关的已有问题记录，把仍适用的修复和检查纳入本次计划。历史问题已修复不等于本次候选已通过，尤其复核字号、遮挡、动作方向、坐标系与参数冲突。

片头片尾等复用素材沿用已有素材目录与来源记录，绑定版本、哈希、时长、音频尾部、文字/字体依赖和适用画幅。新项目复用后仍检查与正文连接处，不能沿用旧片验收结果。

好用的开场、交互、转场和文字效果也进入同一复用记录：保留可编辑组件/配方、预览、来源和依赖版本、适用语义、可调参数、入出状态及限制，不能只收藏成片片段。复用时替换成长中文和本次实际时长检查；一次正向评价先作为候选经验，不自动变成所有视频的默认风格。

每次局部修改记录受影响镜头与相邻接缝，复核相关语义/字幕/音频/字号；共享依赖变化扩大检查范围。保存可编辑工程、审阅版与证据，发布仍按用户授权执行。

评估“低成本/快速完成”时记录实际范围：文案与录音准备、素材获取、首个可看版本、修改轮次、渲染及验收时间，另记可取得的用量/费用与缓存复用情况。区分首稿和最终可交付版本；缺失的成本标为未知，不用作者自述或局部生成耗时代替本地端到端证据。
