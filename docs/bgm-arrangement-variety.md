# 同一音乐基因 BGM：片内变化门禁

更新时间：2026-10-29（Asia/Shanghai）。执行工具：Codex；具体运行模型未独立核验。

保持音乐基因统一，优先选择较长素材，或在叙事边界编排同一家族的不同编曲／同一长素材的不重复段落。不要把单段短 BGM 不停循环铺满全片。既不限定三首，也不要求每条短视频都换音乐。

## 入口与自动处理

1. `music_pipeline._select_music_v2` 在原有家族、授权与评分门禁之内，按全片已选择源区间排除重复候选，然后选择仍合格的候选。允许从排名较低的长素材或另一编曲中选择，不放宽评分和分差要求。不是全局最优搜索；没有合格候选时返回 `needs_creative_selection`，明确要求补充长素材／变奏，不擅自生成、下载或挪动口播边界。
2. `readiness.arrangement_audit` 记录源 SHA、实际源区间、使用时长、重复次数、违规原因、策略与报告 SHA；未解决的选择不能报告完整通过。合同校验会重新计算，不能手改 `render_eligible` 绕过。
3. `video-music-pipeline audit-arrangement --spec <全片BGM清单.json> --output <报告.json>` 是本地编辑器写入前的稳定检查入口。退出码：`0` 通过，`3` 编排违规，`2` 证据／参数错误。素材路径和 SHA 必须匹配；PCM WAV 时长从实际文件头校验，FLOAT WAV 与其他格式复用现有只读 `probe_media_metadata`／FFprobe，不解码混音。传入的时长若与实际不符则拒绝。
4. Node 编辑器适配复用 `scripts/music_arrangement_preflight.mjs` 的 `assertNativeMusicArrangement(plan, {reportPath})`。必须在 `import_asset(s)`、编辑会话写入与媒体复制之前检查全片。当前父母保险项目 V1／V2 适配脚本均已接入；此模块不会连接编辑器、混音或导出。
5. `build_music_mix_command` 也拦截直接传入的过度循环 selection，ducked stem 复用同一检查。它只能检查单个 selection；多段计划仍必须先经过全片合同／CLI 门禁。
6. 编排修改后重新检查，再试听单调感、转场与人声关系；技术门禁通过不能替代试听、响度检查和人工发布决定。

CLI 清单示例（所有 BGM 片段需一次性提交）：

```json
{
  "asset_sources": {
    "warm-a": {"path": "music/warm_story.wav", "sha256": "实际64位SHA", "duration_s": 64}
  },
  "layers": [
    {"asset_id": "warm-a", "timeline_start_s": 0, "duration_s": 54.9,
     "source_start_s": 0, "source_end_s": 64, "loop": false}
  ]
}
```

## 默认可配置判断

参数只保存在 `policies/spoken-bgm-policy.v1.json` 的 `arrangement_variety`，不是另一套混音配置。以下数字是本次实施的可调整默认值，用户原要求没有指定这些秒数。

- 同一 SHA 的同一源区间最多出现两遍。超过部分累计大于 `0.25 秒` 时阻止，能发现显式 loop、拆成多个 clip、改名或别名重用；即使视频短也不允许一秒循环几十次。
- BGM 实际覆盖超过 `30 秒` 时，若一个源占使用量至少 `80%`，其不重复源内容必须达到 `min(60 秒, BGM覆盖时长 × 75%)`。防止 21 秒循环两遍后再加一秒别曲伪装变化。
- 单条长素材、多个真实变奏、同一长文件中不重叠的窗口、短视频的一次播放、明确无音乐均可通过。两段各 20 秒的不同音乐可以编排使用；不要求固定数量。
- 按全片音乐覆盖计算，空白不会虚增所需音乐长度。跨轨淡化不会把同一段复制当成新素材。
- 这是基于素材 SHA 与源时间的确定性检查，不能识别提前烘焙在一个文件里的重复旋律，不能证明不同文件听感不同；这部分仍由完整试听判断。此门禁针对 BGM 铺底，不替代短提示音／音效路线。
