优先前三项，其余按镜头需要使用，允许不选包装。同一时刻优先一个主要视觉强调，字幕仍完整可读。标题、图卡、字幕各司其职，不把同一句话重复三遍。

停帧/回放会改变时长，放在锁定剪辑之前。若后来加入，重新锁定 EDL，重投影字幕、动画、音效、章节和进度条。回放标明“回放”，不制造事件再次发生的错觉；明确声音如何保留/重复/淡出，不能截断半句。

## 2. 从 Caption with Intention 吸收什么

附件为《得到大脑》转写/总结，未附原视频、官方参数表或源码。项目关于动态排字、角色和语气表达的设计思路，可由 [Type Directors Club 项目页](https://tdc.org/winner/caption-with-intention-2/) 交叉确认。这里采纳思路，不声称复现官方系统或已经完成听障受众验证。

### 三种字幕选择

- **standard**：默认稳定短句，保留校对后的完整内容、基本字号与阅读停留；听不清处待核，不猜词补齐。
- **speaker_aware**：多人、画外或易混淆对白，按已核实身份增加“父亲／女儿”“讲解者”等文字标签，固定颜色/位置仅作辅助。不靠颜色单独区分身份，不提前揭示剧情中的未知身份。
- **expressive_trial**：声音表现对理解有价值时做小样。稳定短句上叠加有限强调，保留普通版供比较。当前是创作规范，不是已接通的自动情绪字幕服务。

执行要点：

1. 整个可读短句先显示，再按可靠词时钟选择性强调，避免只剩不断替换的单字。只有句级时间时使用整句显示，不能按字数均分伪造词级同步。
2. 字号沿 typography_gates，轻声不低于下限。动效按最大尺寸检查换行/遮挡，固定行框和基线，避免全句抖动。中文字符覆盖与字重支持分别检查。
3. 声音大小、基频与情绪不等价。背景音乐、麦距和自动增益都会影响测量，不以全混音音量直接判断愤怒/悲伤，不按人物身份推定声线。
4. 附件“低音加粗、高音变小”的具体映射尚未由官方参数材料核验，不写成我们的规则；字幕不能随高音缩到难以阅读。
5. 对理解有作用的非语言声音选择合适表达：表达型字幕可用角色色的拟声文字与节奏动效（父亲笑声的具体修订见下节）；普通版或无法清楚表达时用 `[父亲笑]`、`[门铃响]`、`[轻声]` 等说明。描述可听见的事实，不猜心理。歌曲歌词、有意重复、画外声与重叠对白都检查覆盖，不给每个显而易见的小声响加标签。
6. 关闭动效后台词、角色和必要声音信息仍成立。烧录 MP4 内的文字动效不可由观众关闭；需要选择时另出普通版或实际支持的独立字幕轨。SRT 不能完整保留动态样式。
7. 同一候选做有声、静音与手机尺寸检查。Agent 自评不替代听障受众可用性测试，也不自动构成无障碍合规结论。

参考 [W3C 字幕说明](https://www.w3.org/WAI/media/av/captions/) 对准确、同步及必要非语音信息的要求，以及 [颜色不能成为唯一线索](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) 的原则。三模式与动效取舍是我们的应用设计，并非 W3C 规定模板。

### 2026-10-11 16:27:14 +08:00 | Codex（GPT-6）：静音观看与笑声的直接表现

用户进一步明确：表达型字幕也服务日常静音观看，让观众获得台词之外的角色、重音、停顿、笑声和回应。动效按是否传达这些声音信息选用。

父亲笑声的首选示例：采用项目里已经建立的**父亲角色色**显示“哈哈哈”，跟随原笑声的起止和可确认的节奏出现，然后选择适度缓慢变大，或轻轻上飘、淡出。实际节奏与运动范围在源音及手机预览中确定，本例不指定尚未测量的时间、色值和字号。声音消退时可保留短暂的视觉余韵，不能夸大成原声没有的持续大笑或遮住女儿的反应。

- 角色首次建立时用人物画面、位置对应或简短名字帮助认清，之后“哈哈哈”可以直接表演，不必每次再加“父亲笑”的文字解释；画外或多人重叠而身份不明时补足线索。沿用项目角色色，不能自动指定为品牌色。
- 拟声文字属于独立表现层；已有台词字幕保持稳定，歌词、对白的必读内容不随笑声一起飘走。笑声文字本身从可读字号开始，限制最大尺寸和飘动范围。
- 渐大或飘走是用户认可的设计方向，按这段笑声选择；不强制叠加所有动效，不把同一动画机械用于叹气、哭声等不同声音。
- `[父亲笑]` 保留给普通字幕版、文本导出或身份无法明确的降级表达。表达型版本与普通版本保留相同的必要信息，可以使用不同表现形式。
- 静音验收：能否看出谁在笑、笑声何时开始/结束，以及这次回应的节奏和力度？有声复核：文字的出现与原声吻合，未凭动效添加新的情绪判断。继续检查手机可读性、角色区分和主体遮挡。

本次为设计规则修订，未制作真实素材的笑声动画或新增通用字幕渲染器。

## 3. 从羲和精简工作流吸收什么

下列时间为附件原文定位，未获取/观看原始视频，不代表实际音视频核验。

| 环节 | 采纳动作 | 附件区间与调整 |
|---|---|---|
| 准备 | 简短提纲、两三点结论、展示页面；熟悉的低风险内容可提纲录制 | 00:43–02:30；精确事实、数字与限定仍先审校，不统一取消逐字稿 |
| 试录 | 录一小段，实际听音、看手机尺寸文字、画幅和界面 | 03:25–04:15、06:55–07:39；首次/换设备/换场景重点检查 |
| 展示 | 页面预定位、物件活动范围做场外标记 | 03:25–04:15；标记不进入成片 |
| 分段/标错 | 按完整小章节录，记时间＋问题＋处理意图 | 06:23–06:55、12:36–13:51；不强求一镜到底，保留句首句尾 |
| 导入/筛选 | 可辨认命名，连到既有随拍随选卡 | 13:36–13:51、15:18–16:19；先核对再删明确废片，保留独有/待核内容；本材料不授权删除 |
| 剪辑顺序 | 定画幅 → 删减/重排 → 如需变速先试听并更新映射 → 锁定 → 最终字幕/包装 | 15:18–18:25；字幕草稿、覆盖与基础音量仍从粗剪开始 |
| 字幕反馈 | 比较人工改前改后，提取术语、断句、人名的候选规则，保留反例/词域 | 14:06–14:49、18:38–19:20；复用 feedback/preferences 与词表，不自动改全局规则 |
| 资产复用 | 常用标题、标注、往期封面与关联素材进入既有目录 | 19:51–21:58；绑定版本/题目；贴图本身不能点击跳转 |
| 音乐音效 | 保留无 BGM 的简单路线，音效按动作/期待/重点的实际作用选择 | 21:58–23:18；沿现有 cue 与音效出口，不全局禁用音乐 |

不照搬：

- 全片统一 1.4–1.6 倍速：先判断内容密度、理解与自然语气；歌曲、亲子互动、情绪和笑声默认自然节奏，具体片段变速需显式记录。
- 无声部分一律删除：保留必要观察、动作、思考、呼吸和情绪停留。
- 把字幕删除“嗯／啊”等同于剪掉原声：显示清理与音频编辑分别记录；有意义的否定、犹豫、迟疑不机械删。
- 用 BGM 掩盖录音问题：先改善收音/人声，音乐由表达和听感决定。
- 自动沿用作者快捷键、磁盘路径、贴纸或口癖：先看现有配置，仅吸收方法，不把个人习惯变成全局设置。

字幕反馈写入现有项目复盘：原文/改后、源音区间、纠错类型、适用词域、反例、确认状态。多次获得支持的更正再成为受限规则；人名、金额、否定词、歌词不做无条件替换。
