## 二、实踩的 8 个真坑与工程定律

1. **`libass` `BorderStyle=3` 暗缝与 `BorderStyle=4` 的误判纠偏**
   - 在 `BorderStyle=3, Outline=10` 半透明底框下，行内任何 `{...}` 切样式都会让 `libass` 按 run 各自多画一圈框并水平重叠 ~`20px` 暗条。用全行 `\xbord0` 虽然能消中间暗条，但 `1080p` 原图显示重音处仍有 `4px` 上下沿台阶、首尾字 `0px` 贴死框边；加 `\fscx35 \h` 补衬垫反而打出可见竖缝。
   - **真正解法**：之前淘汰 `BorderStyle=4` 只是因为忘了把 `Outline=10` 清零——在 `libass` 中 `BorderStyle=4` 的 `BackColour + Shadow` 负责整句统一矩形框，而 **`Outline` 依然画字形描边**！设 `Outline=0` 或 `Outline=2` 后，单层 ASS 天然实现 `0px` 台阶、`0` 暗缝与“底框 + 描边”共存（仅限内部锁定 `FFmpeg/libass` 环境）。
2. **禁止只看 `360px` 缩略图做视觉验收**
   - `4px` 的 `\fs74\ybord3` 底框台阶和 `0px` 首尾贴边在 `360px` 预览图上仅剩 `~1.3px`，肉眼很容易误判“无问题”。所有字幕样式改动必须输出 **`1080×1920` 原生 1:1 裁剪板**目视复核。
3. **ASS 缺 `YCbCr Matrix: TV.709` 引发 8 级色偏 & `RGB24 PNG` 测试失真**
   - 在真实 `yuv420p` BT.709 视频上缺失 `YCbCr Matrix: TV.709` 会导致实测色差达 `8` 级（把贴近门槛的浅色直接拉低）；补齐后误差收敛至 `1–2` 级。
   - 用 `ffmpeg -i bg.png`（`RGB24`）直接烧录会触发滤波器内部峰值白映射到 `235`（TV-range）的假降暗；颜色对比度实测**必须跑在真实 `yuv420p bt709` 视频流上**。
4. **FFmpeg `-ss` 放输入前会重置字幕时间戳**
   - 冒烟脚本里曾把 `-ss 4.5` 写在 `-i bg.mp4` 前面，输入帧 PTS 被重置回 `0.0s`，导致 `vf_subtitles` 重复渲染 `0–4s` 的 Cue 1。截取烧录后指定时间点验证帧，`-ss` 必须放在 `-i` 之后（输出侧 seek）。
5. **加描边/阴影是对色彩系统最强的减负**
   - 仅靠 `65%` 半透明底框时，鲜明 `#8EE3FF` / `#FFB499` 对白底合成框只有 `3.5–4.2:1`；加上 `2px–3.5px` 深色描边后，紧邻字口对比度直接跃升至 **`11.3:1`–`19.7:1`**，同时解放了实景配色自由度。`BS=1` 描边+阴影干净通透，`BS=4` 底框+描边适合高对比票据印刷横线场景。
6. **停顿切分与瞬时 CPS 的反例边界**
   - 即使“拼接后文本完整”且“子段都在父 cue 时间窗内”，如果停顿把后半句挤到末尾或中间抽空过长，子段会瞬间超 `CPS > 9.0` 甚至只剩几帧。必须在 **ASS 厘秒量化后**对每个子段独立校验 `visible_duration_s >= 0.50s` 与 `CPS_j <= 9.0`。
7. **审计防误杀比正则剥离更重要**
   - 若审计用正则全局剥除 `^\[.*?\]` 或角色前缀，一旦台词里原本就出现字面量（如 `不爱用"[笑着说]"`），正则就会破坏原文或掩盖篡改。正确做法是编译阶段对 `speaker_label` / `tone_annotation` / `speech` 明确分型，交付期由 `expected_plan` **正向构造**期望串做逐字符全等校验。
8. **`Dengb.ttf` 版权边界与跨引擎字符偏移**
   - `Dengb.ttf`（`DengXian-Bold`）TTFont `nameID[13]` 为微软随产品提供字体，仅允许本机 Windows 位图硬烧录，**严禁随 Git 仓库或 Remotion Web 包再分发**。
   - Python 码点索引与 JavaScript UTF-16 索引对扩展字/emoji（如 `𠮷`）天然错位；编译器必须直接下发经过扩展字素簇边界校验的**预切分 `runs` 数组**，禁止渲染端二次切片。
